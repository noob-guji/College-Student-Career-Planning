## 1. 知识库组成

### 1.1 原始数据结构
知识库的基础数据来源于 `jobs_cleaned.csv`，该数据集包含了大规模的原始招聘信息：
- **核心数据**：【岗位名称】与【岗位详情】是知识提取的重中之重。
- **次要数据**：【地址】、【薪资范围】（包括 `min_salary`, `max_salary`, `salary_month`）、【所属行业】。
- **辅助数据**：【公司名称】、【公司规模】、【公司类型】、【岗位编码】、【更新日期】、【公司详情】、【岗位来源】等辅助维度的信息。

### 1.2 增强数据集结构
基于原始数据，我们深入提炼并生成了 `jobs_enhanced.json`。该数据集涵盖了原始数据中出现过的 62 种标注岗位名称，并从每个岗位的岗位详情中高度凝练出结构化要求，包含专业技能、软能力、所需证书、所需专业以及五个维度的软技能打分（创新、学习、抗压、沟通、实习，均为 1-5 分）。数据结构示例如下：

```json
{
    "岗位名称-1": {
        "专业技能": ["..."],
        "软能力": ["..."],
        "需要的证书": ["..."],
        "需要的专业": ["..."],
        "学历": "......",
        "经验": "......",
        "软技能评分（1-5分）": "创新能力4分，学习能力4分，抗压能力4分，沟通能力5分，实习能力2分"
    }
}
```

### 1.3 关系型数据库（SQLite）结构
系统将结构化特征化繁为简，存储于 SQLite 文件中的 6 个核心数据表中：

1. **`jobs` 表**：包含两万多条直接从原始数据集平行导入的基础数据（如岗位名称、地址、薪资、所属行业、岗位详情等）。
2. **`job_profiles` 表**：将 `jobs_enhanced.json` 解析入库，包含 62 种独立标准岗位名称及其对应的专业技能、软能力、证书要求与五维度打分评价。
3. **`skills` 表**：两列结构，存储了自数据集中提取合并的 638 个标准化技能条目。
   - `skill_id`：技能的唯一编号（主键，从 1 开始递增）。
   - `skill_name`：标准化后的技能名称（唯一不重复、无空格、格式统一）。
4. **`skill_relations` 表**：存储技能与技能间的“边与权重”网络关系。
   - `skill_id1` / `skill_id2`：关联技能对的唯一 ID。
   - `relation_type`：关系类型（固定使用 `related_to` 表示相关）。
   - `weight`：关联权重（技能共现次数，数值越大关联性越强）。
   - *过滤规则*：仅保留共现次数 $\ge 2$ 的强关联对，剔除无效弱关联。
5. **`skill_synonyms` 表**：技能同义词表，记录不同形式但含义一致的技能映射（存储 `skill_id` 与对应 `同义名称`）。
6. **`skill_hierarchy` 表**：技能层级表，以树状形式存储并映射 `父分类` 与 `子技能`。

### 1.4 向量数据库结构
对于纯文本与复杂语义的匹配，系统部署了两种独立的非结构化高维向量数据结构：

1. **岗位向量数据库（Chroma）**：
   - 将原始数据（两万余条记录）逐一全量向量化。
   - **文本数据 (Document)**：截取由“岗位名称 + 岗位详情 + 所属行业”拼接而成的大段文本。
   - **元数据 (Metadata)**：附带存储数据编号、岗位名称、最低薪资、地址、所需技能等特征，便于检索后的结构化过滤与展示。
2. **技能向量数据库（FAISS）**：
   - 专门对 SQLite `skills` 数据库表中的所有标准技能条目词汇进行向量索引封装。
   - **内容**：包含了技能名称与其向量之间的绝对映射关系及关联的技能 ID。旨在对用户输入的非标准生僻技能词进行近义语义快速锚定。

### 1.5 垂直晋升数据库结构
垂直晋升路径以结构化的 JSON 格式（`vertical_paths.json`）存储，展示了基于职能大类的垂直职业发展阶梯：
- **`meta`（元数据）**：
  - 记录统计信息（如 46 个大类，31 种具体岗位等）。
  - `data_driven` 属性释义（`true` 表示融合了历史招聘数据基于同一公司的真实薪资排序结果；`false` 表示纯业务规则推断）。
- **`category_paths`（核心路径数据）**：包含各职能大类（如“Java开发”、“测试工程师”等）的晋升路线：
  - `full_ladder`：该大类下完整的晋升阶梯数组（如：实习生 → 初级开发 → 开发工程师 → 高级开发 → 架构师 → 技术经理 → 技术总监）。
  - `data_driven`：标识该具体路径是否由真实数据驱动。
  - `paths_by_level`：根据不同的起步层级（"初级"、"中级"、"高级"）动态划分的后续前向晋升目标列表。

### 1.6 水平转岗数据库结构
水平转岗路径以结构化的 JSON 格式（`lateral_paths.json`）存储，展示了基于岗位技能相似度推算的跨界转岗机会：
- **`meta`（元数据）**：
  - 记录向量来源（如 `TF-IDF` 兜底）、覆盖的核心岗位数量，以及截取的 Top-N 数量。
  - `description` 释义（相似度分数基于 0-1 的余弦相似度，得分越高代表技能重合度越大，难度越低）。
- **`lateral_paths`（核心对象列表）**：以源岗位（如“前端开发工程师”）作为 Key：
  - `source_job`：起始岗位名称。
  - `paths`：排名前 N 的极具潜力的转岗目标列表，每个路径节点深度包含：
    - `目标岗位`：转岗方向。
    - `相似度得分`：技能或文本的重合度得分。
    - `所需补充技能`：为了完成转岗需要额外学习的技能建议（数组格式）。
    - `难度`：综合评定的跨界难度（如“高”、“中”）。
    - `预计过渡周期`：转岗需要适应或付出的时间成本（如“6-12个月”）。
    - `推荐行动`：具体的执行建议（如“考取相关认证”、“寻找内部轮岗机会”等）。
    - `薪资变化参考`：对应的薪酬波动预期范围。

## 2. 数据库构建方法

本项目的数据构建分为三大模块：岗位知识库、技能知识库、晋升/转岗知识库。

### 2.1 岗位知识库构建

岗位知识库由结构化的“岗位结构库”与非结构化的“岗位向量库”两部分构成。

#### 2.1.1 岗位结构库（SQLite）
- **编写脚本**：`local_knowledge_base/scripts/build_jobs.py`
- **作用**：
  将清洗后的 `jobs_cleaned.csv` 基础岗位数据与通过 AI 增强的 `jobs_enhanced.json` 画像数据进行深度整合与结构化存储。它通过建立 SQLite 关系型数据库，不仅实现了对两万多条原始招聘记录的去重与标准化，还利用逻辑匹配将 AI 提取的技能、证书及五维能力评分精准地分发到对应的岗位节点上。从而将零散的扁平文件转化为具备主外键关联的结构化知识池，为后续 RAG 架构中的精确 SQL 查询和多维人才画像匹配提供坚实的数据底层支撑。
- **输入**：
  - `local_knowledge_base/data/processed/jobs_enhanced.json`
  - `local_knowledge_base/data/processed/jobs_cleaned.csv`
- **输出**：
  - `local_knowledge_base/database/knowledge.db`（SQLite 数据库文件）
- **数据表结构**：
  1. **`jobs`（基础信息表）**：
     - 存储约 21140 条（或根据清洗规则确定的数量）唯一岗位记录。
     - **字段**：岗位编码（主键）、岗位名称、公司名称、工作地点、薪资描述、岗位详情、`min_salary`（最低薪资）、`max_salary`（最高薪资）。
  2. **`job_profiles`（画像增强表）**：
     - 通过 `job_id`（岗位名称）与 `jobs` 表实现外键关联。
     - **画像维度**：存储以 JSON 格式序列化的 `skills`（技能列表）和 `certifications`（证书列表）。
     - **五维评分**：存储数值化的 `innovation`（创新）、`learning`（学习）、`stress`（抗压）、`communication`（沟通）、`internship`（实习），分值范围为 1-5 分。

#### 2.1.2 岗位向量库（Chroma）
- **编写脚本**：`local_knowledge_base/scripts/build_jobs_vector.py`
- **作用**：
  将非结构化的招聘文本转化为机器可理解的高维语义空间。它利用 `BAAI/bge-base-zh-v1.5` 模型将岗位名称、详情描述、技能标签及行业背景深度融合为一个 768 维的稠密向量。通过 ChromaDB 持久化存储，该库突破了传统关键词检索的局限，使得语义相近的岗位能够被精准召回，为后续的智能岗位推荐、语义搜索和 RAG（检索增强生成）提供 AI 核心动力。
- **输入**：
  - `local_knowledge_base/data/processed/jobs_cleaned.csv`
  - `local_knowledge_base/data/processed/jobs_enhanced.json` 
  - AI 模型：`BAAI/bge-base-zh-v1.5`（中文向量模型）
- **输出**：
  - `local_knowledge_base/vector_db/chroma/`（Chroma 持久化文件夹）
- **运行规范**：
  1. **文本块构建**：拼接 `[岗位名称] + [岗位详情(前300字)] + [专业技能标签] + [所属行业]`。
  2. **向量特征**：生成 768 维向量（由原生模型输出或截断处理），使用 `Cosine`（余弦相似度）作为度量空间度量。
  3. **数据条目 (Collection)**：
     - **ID**：使用自增 `row_index`（1, 2, 3...）作为主键，确保唯一性。
     - **Metadata**：存储 `row_index`、`title`、`skills`、`industry` 及 `min_salary`。
     - **Document**：存储构建后的组合文本块内容。

### 2.2 技能知识库构建

技能知识库同样由关系型的“技能结构库”与辅助语义匹配的“技能向量库”组成。通过对原始职位描述中的专业术语进行重构，提取出标准的专业技能清单以及技能相关性网络。

#### 2.2.1 技能结构库（SQLite）
技能结构库的构建包含三个核心环节，分别负责基础词汇表初始化、共现关系分析和高级语义与层级挖掘。
- **编写脚本**：
  - `local_knowledge_base/scripts/build_skills(1).py`
  - `local_knowledge_base/scripts/build_skill_relations.py`
  - `local_knowledge_base/scripts/build_skill_advanced_relations.py`
- **作用**：
  基于清洗后的 `jobs_enhanced.json`，完成基础底层词汇表的去重提取与泛化标准化（全部转为小写、去除空格）。计算不同技能在同一岗位需求中的无向“共现组合”以生成技能关联网络图，之后结合预定义的深度分类规则与 AI 相似度模型完成包含同义词汇融合、专家派系图谱构建在内的整个大知识网扩容。该库主要为系统中技能溯源推荐与相关能力推演提供了显式的底层逻辑树干。
- **输入**：
  - `local_knowledge_base/data/processed/jobs_enhanced.json`
  - 内部上游生成的 SQLite 测试数据（如 `skills` 表数据）与内置代码专家树常量。
  - AI 模型：`BAAI/bge-large-zh-v1.5`（用于挖掘潜在异形同义词）。
- **输出**：
  - `local_knowledge_base/database/knowledge.db`（向统一知识库继续追加四大特征表）
  - `local_knowledge_base/data/processed/skills_master.csv`
- **运行规范与表结构**：
  1. **`skills` 表（基础词汇）**：利用 `build_skills` 脚本读取 JSON，提取被清理去重后的统一词汇名单进行库表覆盖写入（`replace`），包括表键 `skill_id` 与唯一名 `skill_name`。
  2. **`skill_relations` 表（图谱网）**：利用 `build_skill_relations.py` 统计职位对技能集进行笛卡尔无向积组合，记录组合关联权重（`weight`频次），硬过滤筛除出现不足两回的弱关联噪点（`count < 2` 为抛弃阈限）。
  3. **`skill_synonyms` 表（同义聚类）**：先通过空格等非标准格式作为特征直接合并近似别称，并针对剩下的生僻术语使用 FAISS `IndexFlatIP` 内积比对计算各词汇近邻节点前五强（阈值限定 Score > `0.7`），合并有效词系并统一落表关联主键。
  4. **`skill_hierarchy` 表（知识分类层级）**：调用内置“行业归属”四级深度字典树，构建专门的 `insert_hierarchy` 函数施行深度优先递归 (DFS) 处理并逐节填入 `parent_skill` 给 `child_skill` 指派上级族裔挂载。

#### 2.2.2 技能向量库（FAISS）
- **编写脚本**：`local_knowledge_base/scripts/build_skill_vectors(1).py`
- **作用**：
  充当整体系统的独立离线计算衍生基建组件（完全剥离复杂关系引擎运行逻辑）。它的首要目标是从纯结构化纬度表抽取有效纯文字实体技能，并在内部转化建立完整的稠密高维 FAISS 平面库，以应对非标或白话文表述形式生僻查询时能够快速脱胎寻找锚点，用高计算维系代替关键词 like 硬推逻辑以确保低延迟和高泛指正确率。
- **输入**：
  - `local_knowledge_base/database/knowledge.db`（提取 `skills` 表内全量名称清单）
  - AI 编码器组件：`BAAI/bge-large-zh-v1.5`
- **输出**：
  - `local_knowledge_base/vector_db/skill_vectors/skills.index` (FAISS 专用原生向量索引集合)
  - `local_knowledge_base/vector_db/skill_vectors/skill_names.npy` (纯 numpy 数组的词汇映射映射数据块)
- **运行规范**：
  1. **特征分离与抽取全量**：拉取库内标准名称名录，运用 `SentenceTransformer` 的编码机制进行表征归一操作映射成一维稠密结构点群。
  2. **FAISS 高效索引与封装**：无需开启外部 Chroma 数据库环境支持与服务配置操作，依靠单点本地依赖加载 FAISS 定长维度的平面暴力内积矩阵结构树（`IndexFlatIP`）。
  3. **存算分离落盘策略**：强制分离元数据和数字几何库数据实体；主体的 Vector 流打包给 `.index` 库并独立计算距离，而所有的单词源文字直接打包映射为轻量 `.npy` 矩阵文件保障毫秒级别的关联查询。

### 2.3 垂直晋升/水平转岗知识库构建

垂直晋升/水平转岗知识库由结构化的"岗位图谱库"与可选的"图数据库导出"两部分构成，涵盖了从垂直晋升、水平转岗到 Neo4j 图数据库导出的完整环节。

#### 2.3.1 垂直晋升路径构建
- **编写脚本**：`local_knowledge_base/scripts/build_vertical_paths.py`
- **作用**：
  本模块主要负责提取职位序列并生成结构化的垂直晋升链条。系统采用了"双轨路径构建"机制：优先通过历史数据中"同一公司+职能大类"进行薪资排行时序分析，推测出企业真实的晋升路线；若数据中缺乏有效的变动记录，则会启用兜底策略，利用内置模板与职级关键词（0至10级，涵盖实习、初级、中级到总监、C-Suite等）进行职位位置插补和推断。
- **输入**：
  - 自动搜寻 `data/raw/` 目录或当前目录下的 `jobs_cleaned_1.xls` 与 `jobs_cleaned_2.xls` 文件，并首个关联合并为 `jobs_cleaned.csv` 数据集。
- **输出**：
  - `local_knowledge_base/data/knowledge_graph/vertical_paths.json`
- **核心逻辑与运行规范**：
  1. **数据驱动真实路径（优先）**：依据`公司名称`与提取的`职能大类`双重分组，通过计算该组内相同岗位薪资中位数的排序关联推导真实演进关系。
  2. **规则推断路径（兜底）**：针对 46 个定义好的职能大类使用 `CAREER_LADDER_TEMPLATE` 模板预设晋升阶梯；当前目标若未在标准阶梯内，则依靠模糊名称等级测算来落定层阶。
  3. **输出结构化**：以 JSON 格式结构化输出全局 `meta`、46 个划分大类的 `category_paths` 树（含初、中、高级划分节点），以及针对每个有效原始提取岗位的 `job_paths` 字典。

#### 2.3.2 水平转岗路径构建
- **编写脚本**：`local_knowledge_base/scripts/build_lateral_paths.py`
- **作用**：
  本模块旨在通过高维空间几何相似度计算寻找跨岗位的机会。系统对定义的 10 个核心岗位寻找前 Top-N（常用 Top-5）的可转岗方向。转岗数据不仅包含几何距离，更融合了自带的跨界领域策略矩阵（`SKILL_GAP_RULES`），自动补充了"所需补充技能"、"难度评估"、"预计过渡周期"、"推荐行动"以及预期的"薪资波动幅况"等详尽规则指导。
- **动态输入与三级寻址策略**：
  - **最优策略（ChromaDB Client API）**：当发现 `vector_db/chroma` 目录且含有合规 Python 环境时优先触发向量调取。
  - **兼容策略（SQLite 直读机制）**：若无 Client 支持，直读解析底层的 `chroma.sqlite3` 表的 `embedding_metadata` 与二进制 FLOAT32 数组，完成数据降级提取。
  - **离线兜底策略（TF-IDF）**：若上述机制彻底丢失向量时，降维使用 sklearn 提取 `jobs_cleaned.csv` 的纯文本描述构建最高 3000 特征词的 TF-IDF 离线字典进行近似演练。
- **输出**：
  - `local_knowledge_base/data/knowledge_graph/lateral_paths.json`
- **难度度量逻辑**：
  根据向量余弦绝对分数先得出基础转化评价（$\ge 0.8$为低难度，$< 0.65$为高难度），随后取此评级分数关联与内部专家领域库所规定的难度两者间的"最大阈限"，以此作最终评价输出。

#### 2.3.3 Neo4j 图数据库导出
- **编写脚本**：`local_knowledge_base/scripts/build_neo4j_export.py`
- **作用**：
  旨在将之前生成的两份关系路径 JSON（垂直体系与水平网络）转换为可供 Neo4j 的原生只读加载 Cypher 语法引擎直录入文件（`.cypher`）。
- **输入**：
  - `vertical_paths.json` 与 `lateral_paths.json`
- **输出**：
  - `local_knowledge_base/data/knowledge_graph/neo4j_export.cypher`
- **图模型架构与 Cypher 生成逻辑**：
  1. **强力约束与索引**：脚本会自动在文件头部注入 `CREATE CONSTRAINT IF NOT EXISTS`（使得节点 `name` 在入库时 UUID 保持绝对唯一）与 `CREATE INDEX` 优化，方便高吞吐量查找图元。
  2. **幂等创建机制（MERGE）**：所有的节点对象（`JobCategory`、`JobPosition`）和边界（`BELONGS_TO`、`PROMOTES_TO`、`TRANSFERS_TO`）一律严卡使用 `MERGE` 语法替代传统的 `CREATE`。这能够确保整体录入脚本可以抛开先决条件地被重复、分批次运行。
  3. **丰富节点与属性**：自动把转岗图谱在水平方向所涉及到的字典指导项（`required_skills`, `recommended_action`, `salary_change_ref`）转译为特定边的附加关联参数字典进行入库挂载，降低主键库负荷。
- **运行测试**：
  该导出脚本所附带完整头部注释指引，一键通过命令行执行 `cypher-shell -u neo4j -p <password> --file neo4j_export.cypher` 实现无界面图数据库注入。

在了解了上述各种底层数据库以及关系图谱的数据结构和构建方法后，您可以直接利用项目提供的聚合联调脚本来一键拉起或检测服务。

- **一键生成（初始化）**：直接在根目录下运行 `python scripts/init_db.py`。该脚本按依赖顺序编排了全部的数据库构建流，一键即可拉起从纯净文本依次构建出 `knowledge.db`、`Chroma`、`FAISS`、`JSON 岗位脑图` 再到 `Cypher 图数据库脚本` 导出的所有 9 个流水线核心系统任务。

## 4. 准确率测试

`test_accuracy.py` 是一个用于自动化测试知识库匹配准确率的验证脚本。它包含两个核心评测阶段：
1. **画像属性抽取准确率验证**（提取职位硬技能/软技能的准确程度）。
2. **学生技能到匹配岗位的召回评测**（依据学生技能对相应岗位的召回表现）。

### 4.1 依赖与环境
脚本在运行前需要满足以下依赖要求：
- **核心依赖库**: `sentence-transformers` 和 `chromadb`
- **模型下载环境**: 为了避免国内网络导致的下载失败，脚本开始会自动将 `HF_ENDPOINT` 配置为 `https://hf-mirror.com`。

### 4.2 核心功能拆解

#### 4.2.1 阶段一：画像准确率验证 (`run_profile_accuracy_test`)
该阶段负责评估预处理的 JSON 抽取结果 (`extracted_results.json`) 与数据库已有标准之间的对齐准确率。

- **验证流程**:
  1. **构建扩展技能池**: 结合数据库表（`skills`, `skill_synonyms`）与本地规则配置（`skill_extraction_rules.json`），创建当前岗位的同义词扩展技能池。
  2. **硬匹配**: 将测试样本的硬技能特征直接与扩展技能池通过字面规范化后比对，统计精确命中数。
  3. **语义软匹配**: 针对**硬匹配失败**的技能特征，利用 `BAAI/bge-large-zh-v1.5`（1024维大模型）将未命中技能与数据库存量技能进行向量计算（余弦相似度），在相似度 `score >= 0.60` 时亦算作命中扩充覆盖面。
  4. **误差计算 (MAE)**: 计算创新能力、学习能力、抗压能力等 5 项软技能的评分绝对误差平均值。

- **判定标准**: 预测准确当且仅当满足 **技能覆盖率 >= 65%** 且 **软技能 MAE <= 2.0**。

#### 4.2.2 阶段二：匹配准确率验证 (`run_matching_accuracy_test`)
该阶段使用 Chroma 本地向量库评估模拟候选人 (`test_mock_students.json`) 的求职召回能力，使用的关键指标是 **Recall@5**。

- **验证流程**:
  1. **拼接特征词**: 将每名学生的各项零碎子技能连接为一段文本查询("技能侧写: xxx")。
  2. **模型降维适配**: 注意该函数使用的是 `BAAI/bge-base-zh-v1.5`（768维），因为基础的 Chroma 向量数据库是用 base 模型建立的，如用 large 版进行推断会导致维度报错崩溃。
  3. **计算召回 (Recall@5)**: 调用 ChromaDB 在其中索取前 5 位最相近的岗位数据。
  4. **命中判定法则**: 目标靶向岗位只要在命中 TOP-5 职位的 `title` 中（相互包容即可例如"Java开发工程师"和"Java后端"视为命中），均视为 **Hit**。

- **判定标准**: 要求整体样本计算得出的 **Recall@5 >= 80%**。

### 4.3 关键文件路径
- **真实基准数据**: `data/processed/test/extracted_results.json`
- **模拟学生数据**: `data/processed/test/test_mock_students.json`
- **本地 SQLiteDB**: `database/knowledge.db`
- **Chroma 向量库**: `vector_db/chroma`
- **提取规则配置**: `config/skill_extraction_rules.json`
